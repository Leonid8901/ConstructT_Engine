# Триггеры и таймеры

Два маленьких, но нужных почти в любой игре механизма: «кто вошёл в зону / вышел из неё» (`include/CE/Grave.h`, `Entity::OnTriggerEnter/Exit`) и «сделай через N секунд / каждые N секунд» (`include/CE/Timer.h`, объект `Timer`).

## 1. Триггеры

Триггер — тело с `BodyDesc::trigger = true`: физического отклика нет, только события.

```cpp
BodyDesc z;
z.type = BodyType::Static; z.shape = Shape::Box({2, 1, 2}); z.trigger = true;
Entity zone = World.Spawn().SetPosition({0, 1, 0}).AddBody(z);

zone.OnTriggerEnter([](Entity other) { /* other вошёл */ })
    .OnTriggerExit ([](Entity other) { /* other вышел */ });

std::vector<Entity> inside = Grave.Overlapping(zone);   // кто внутри сейчас
bool in = Grave.IsInside(zone, player);
Grave.OnTrigger([](const TriggerEvent& e) { /* e.zone, e.other, e.enter — для всех зон сразу */ });
```

Что гарантируется:

- События приходят в главном потоке после физики, до синхронизации кадра. Внутри обработчика можно трогать мир (команды применяются сразу), создавать таймеры, звать `Overlapping`.
- Вход и выход всегда парные. Если тело внутри зоны **удалили**, выход всё равно приходит (`other.Valid() == false`): счётчики «сколько внутри» не расходятся. Если удалили саму зону, события не приходят.
- Тело, вошедшее и удалённое в том же кадре, входа не даёт.
- Спящее или неподвижное тело внутри зоны остаётся внутри: оно не «выходит» и не «входит заново», когда засыпает или просыпается. Раньше (до этой версии) такие тела выпадали из зоны на время сна и давали ложный повторный вход.
- Удаление или добавление любых других тел (`RemoveBody`, `Destroy`) на состояние зоны не влияет. Раньше любое удаление сбрасывало все пары триггеров, и тела внутри зон «входили» повторно.
- Несколько зон на одном теле — события приходят для каждой. Зона может быть и динамической/кинематической (движущаяся зона); два триггера друг с другом тоже дают события для обеих сторон (если хотя бы один из них не `Static`).
- Повторный вызов `OnTriggerEnter/Exit` на той же зоне **добавляет** ещё один обработчик, а не заменяет. Обработчики умерших зон убираются сами (раз в несколько секунд).
- `Grave.OnContact` по-прежнему получает вход в триггер (`ContactEvent::trigger == true`), выходов там нет.
- Слои работают как у обычных тел (`layer` / `mask`): зона видит только тех, с кем её слои пересекаются.

Пределы: «внутри» означает «тела касаются или перекрываются с зазором до 2 см» (как у обычных контактов), а не «центр внутри». Тело ровно на границе может дрожать вход/выход: если это важно, добавьте задержку таймером. Две статические сущности друг с другом события не дают. Проверка идёт каждый шаг физики (120 Гц) для всех пар «зона + тело» в пересечении габаритов, включая спящие тела: тысячи спящих тел в одной зоне — это тысячи проверок на шаг.

## 2. Таймеры

```cpp
Timer.After(3.0f, [] { door.Destroy(); });                       // один раз через 3 с
TimerHandle t = Timer.Every(0.5f, [] { SpawnWave(); });          // пока не отменят
Timer.Every(1.0f, [] { Tick(); }, Entity{}, 10);                 // ровно 10 раз
Timer.After(5.0f, [] { Explode(); }, bomb);                      // отменится сам, если bomb удалён
t.Cancel(); t.Active();
```

- Время — игровое: идёт вместе с кадрами движка (dt). Окно свёрнуто — не идёт (кадры стоят).
- Функции вызываются в главном потоке после физики, в порядке времени срабатывания (при равенстве — в порядке создания). Внутри можно создавать и отменять таймеры, в том числе самого себя (`handle.Cancel()`), трогать мир, звать любые API.
- Точность — один кадр: функция вызывается в первом кадре, когда время вышло, не раньше. Повторяющийся таймер после долгого кадра догоняет пропущенные срабатывания (не больше 16 за кадр), остальные пропускает, чтобы не копить долг.
- `owner` — сущность, с которой таймер живёт: удалили её — таймер отменяется (проверка раз в кадр, перед срабатыванием).
- `After` с отрицательным или нулевым временем сработает в ближайшем кадре, а не немедленно.
- Создавать, отменять и опрашивать таймеры можно из любых задач UniX (потокобезопасно). Таймер, созданный в `OnStart`, начинает отсчёт с первого кадра.
- Функция таймера не должна работать долго: она выполняется в главном потоке между кадрами. Тяжёлое — в задачу UniX.

## 3. Порядок в кадре

`Update → Flush → Simulate (Grave.Step) → события контактов и триггеров → таймеры → Flush → …`. Таймеры идут сразу после событий физики, поэтому обработчик триггера, поставивший `Timer.After(0, ...)`, увидит срабатывание уже в следующем кадре.
