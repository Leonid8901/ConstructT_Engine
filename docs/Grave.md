# Grave — физика твёрдых тел

Grave — подсистема уровня Actor. Тела создаются через `Entity::AddBody`. Шаг симуляции — задача `Grave.Step` в стадии Simulate.

## 1. Возможности

- Формы: сфера, бокс, капсула, бесконечная плоскость.
- Типы тел: `Static`, `Dynamic`, `Kinematic`.
- Контакты: до 4 точек на пару, спекулятивные контакты.
- Решатель: последовательные импульсы (sequential impulses) с warm starting, трением в центре пятна контакта и кручением, split impulse для проникновения.
- Острова связности (union-find), параллельное решение островов, сон по островам.
- Триггеры, слои и маски, `Raycast`, события контактов.

## 2. Данные

### 2.1 `Shape`

```cpp
struct Shape {
    enum class Type : uint8_t { Sphere, Box, Capsule, Plane };
    Type type;
    Vec3 size;
    static Shape Sphere(float radius);
    static Shape Box(Vec3 halfExtents);
    static Shape Capsule(float radius, float halfHeight);
    static Shape Plane();
};
```

| Форма | `size` | Примечание |
|---|---|---|
| Sphere | `x` = радиус | |
| Box | полуразмеры по осям | |
| Capsule | `x` = радиус, `y` = полувысота цилиндрической части | ось капсулы — локальная Y |
| Plane | не используется | нормаль — локальная +Y сущности, проходит через её позицию; только `Static` |

Коллайдер не зависит от `Scale` сущности. Для примитивных мешей `Mesh::Cube()` (1×1×1) подходит `Shape::Box({0.5f, 0.5f, 0.5f})`, для `Mesh::Sphere()` (диаметр 1) — `Shape::Sphere(0.5f)` при `Scale = 1`.

### 2.2 `BodyDesc`

| Поле | По умолчанию | Описание |
|---|---|---|
| `type` | `Dynamic` | `Static`, `Dynamic`, `Kinematic` |
| `shape` | Box 0,5³ | форма |
| `mass` | 1 | масса, кг (для `Dynamic`) |
| `friction` | 0,5 | коэффициент трения |
| `restitution` | 0,1 | упругость |
| `linearDamping` | 0,01 | линейное затухание |
| `angularDamping` | 0,05 | угловое затухание |
| `trigger` | `false` | без физического отклика, только события |
| `lockRotation` | `false` | запрет вращения (персонажи) |
| `layer` | 1 | битовая маска слоя тела |
| `mask` | `0xFFFFFFFF` | слои, с которыми тело взаимодействует |

Пара взаимодействует, если `(a.layer & b.mask) != 0` и `(b.layer & a.mask) != 0`.

## 3. Справочник API

### 3.1 Глобальный объект `Grave`

| Метод | Описание |
|---|---|
| `void SetGravity(Vec3 g)` / `Vec3 Gravity()` | гравитация, м/с² |
| `void SetSolverIterations(uint32_t n)` | итерации решателя; значение ограничивается диапазоном 1…64; по умолчанию 10 |
| `void SetFixedRate(float hz)` | частота фиксированного шага; по умолчанию 120; значение ограничивается диапазоном 15…1000 Гц |
| `bool Raycast(Vec3 origin, Vec3 direction, float maxDistance, RaycastHit& hit, uint32_t mask = 0xFFFFFFFF)` | ближайшее пересечение; триггеры игнорируются; `mask` сравнивается с `layer` тела; потокобезопасен, можно вызывать из `ParallelFor`; ускорен BVH (§4.3) |
| `void OnContact(std::function<void(const ContactEvent&)>)` | обработчик новых контактов и входов в триггеры; вызывается в главном потоке |
| `void OnTrigger(std::function<void(const TriggerEvent&)>)` | входы и выходы всех триггеров; главный поток ([Triggers.md](Triggers.md)) |
| `std::vector<Entity> Overlapping(Entity zone)`, `bool IsInside(Entity zone, Entity other)` | кто сейчас внутри зоны |
| `uint32_t BodyCount()` | число тел |
| `uint32_t AwakeBodyCount()` | число бодрствующих тел |

### 3.2 Результаты

```cpp
struct RaycastHit    { Entity entity; Vec3 point; Vec3 normal; float distance; };
struct ContactEvent  { Entity a, b; Vec3 point; Vec3 normal /* от a к b */; bool trigger; };
```

### 3.3 Методы `Entity`, относящиеся к физике

| Метод | Описание |
|---|---|
| `Entity& AddBody(const BodyDesc&)` | добавить тело |
| `Entity& RemoveBody()` | удалить тело |
| `bool HasBody() const` | есть ли тело |
| `Vec3 Velocity() const` | линейная скорость |
| `Entity& SetVelocity(Vec3)` | задать линейную скорость |
| `Entity& SetAngularVelocity(Vec3)` | задать угловую скорость |
| `Entity& AddForce(Vec3)` | сила; накапливается и действует на все фиксированные шаги текущего кадра, затем обнуляется |
| `Entity& AddImpulse(Vec3)` | мгновенное приращение скорости `Δv = j / m` |

После шагов Grave записывает `pos`, `rot` и `velocity` каждого бодрствующего нестатического тела в сущность (стадия Simulate, мир в это время никто другой не пишет). Рендер читает их в стадии Prepare. `SetGravity` пробуждает все тела.

## 4. Шаг симуляции

Время кадра ограничивается 0,1 с и накапливается; расходуется фиксированными шагами `dt = 1 / rate`. За один кадр выполняется не более 8 шагов; при достижении предела накопленный остаток сбрасывается (защита от «спирали смерти»).

Шаг:

1. **Интегрирование скоростей** (гравитация, силы, затухание).
2. **Broadphase** — sweep-and-prune по оси X, сортировка вставками (близко к O(n) при когерентном движении). Расширение AABB — 0,03 м. Плоскости проверяются отдельно против AABB всех тел. Пара отбрасывается, если оба тела неактивны, либо ни одно не динамическое и не триггер, либо не проходит фильтр слоёв. `Kinematic` считается активным, пока его скорость ненулевая.
3. **Narrowphase** (параллельно по парам) → контактные многообразия. Спекулятивный зазор — 0,02 м.
4. **Острова** — union-find по контактам между динамическими телами (статические и кинематические тела острова не объединяют). Остров, в котором есть хотя бы одно бодрствующее тело, просыпается целиком.
5. **Решатель** (параллельно по островам):
   - warm starting из импульсов прошлого шага;
   - `iterations` итераций последовательных импульсов;
   - трение решается в центре пятна контакта: две касательных и кручение вокруг нормали;
   - проникновение: смещение через **split impulse** (псевдо-скорости, не добавляют энергию в реальные скорости); итераций split — `max(4, iterations / 2)`.
6. **Интегрирование позиций.**
7. **Сон.** Остров засыпает целиком, когда у всех его тел скорости ниже порогов в течение 0,5 с.

### 4.1 Пары форм

Поддерживаются все сочетания sphere/box/capsule/plane. Box–box: SAT по 15 осям с клиппингом граней, до 4 контактных точек.

### 4.2 Константы

| Константа | Значение | Смысл |
|---|---|---|
| Частота шага | 120 Гц | `SetFixedRate` |
| Максимум шагов за кадр | 8 | |
| Итерации | 10 | `SetSolverIterations`, диапазон 1…64 |
| Спекулятивный зазор | 0,02 м | |
| Расширение AABB | 0,03 м | |
| Baumgarte | 0,2 | коэффициент коррекции позиций |
| Slop | 0,01 м | допустимое проникновение |
| Макс. скорость коррекции | 4 м/с | |
| Порог упругости | 1 м/с | ниже — удар считается неупругим |
| Порог сна, линейный | 0,1 м/с | |
| Порог сна, угловой | 0,2 рад/с | |
| Время покоя до сна | 0,5 с | |

### 4.3 Raycast

Для лучей держится BVH по AABB тел (медианное разбиение по самой длинной оси центров, листья до 4 тел, обход с ближнего ребёнка). Дерево строится раз в кадр на главном потоке после физики и Flush мира (`RefreshQueries`), только если тела менялись; при этом AABB движущихся тел пересчитываются по текущим позициям. Плоскости проверяются отдельно. Пока дерево не построено (например, сразу после `AddBody` в той же стадии), `Raycast` перебирает тела линейно — результат тот же.

Замер (Release, 2 ядра, 20 000 лучей длиной 60 м): 264 тела — 58 → 13 мс, 1000 тел — 241 → 26 мс, 3000 тел — 581 → 29 мс; построение дерева 0,06 / 0,3 / 0,9 мс. Результаты совпадают с линейным перебором.

## 5. События

`OnContact` вызывается в главном потоке после стадии Simulate для каждого нового контакта и каждого входа в триггер. Для триггера `ContactEvent::trigger == true`. Выходы из триггера, список «кто внутри» и обработчики для одной зоны — в [Triggers.md](Triggers.md).

## 6. Известные ограничения

- Нет CCD: очень быстрые мелкие тела могут проходить сквозь тонкие объекты. Спекулятивный зазор (0,02 м) смягчает, но не устраняет эффект.
- Нет шарниров и меш-коллайдеров.
- Высокие плотные стены (≈ 10×5 боксов) могут не засыпать; для очень высоких стопок помогает частота 240 Гц.
- Параллельность по островам: один большой остров решается в одном потоке.
