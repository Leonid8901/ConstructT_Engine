# Amper — рендер и освещение

Amper — подсистема уровня Actor. Растеризация PBR всегда включена; тени от солнца считаются одним из двух способов, выбор которого определяется флагом ray tracing.

## 1. Конвейер

Подготовка (`Amper.Prepare`, стадия Prepare, параллельно):

1. Сбор видимых (`SetVisible`) сущностей и группировка по мешам (счётчики → смещения).
2. Формирование `FrameUbo` (матрицы, солнце, небо, каскады) и списка точечных источников (максимум 256; лишние игнорируются).
3. Параллельно по сущностям: данные инстанса, инстанс TLAS (при RT) и отсечение (§1.1).
4. Компактные списки индексов прошедших отсечение инстансов: для камеры и для каждого каскада, по одному непрерывному диапазону на меш.

Рендер (`Renderer::Render`, главный поток):

| Шаг | RT включён | RT выключен |
|---|---|---|
| 1 | сборка TLAS (по одному на кадр в полёте) | — |
| 2 | — | проход каскадных карт теней (если `Shadows()`) |
| 3 | небо (полноэкранный треугольник); при MSAA — в мультисэмпловую цель | то же |
| 4 | инстансированная отрисовка мешей, один `vkCmdDrawIndexed` на меш | то же |
| 5 | при MSAA — resolve (усреднение сэмплов) в изображение swapchain в конце прохода; present | то же |

Используются Vulkan 1.3 dynamic rendering и synchronization2. Кадров в полёте — 2.

Данные, которые CPU пишет каждый кадр (инстансы, индексы отрисовки, UBO, свет, инстансы TLAS), лежат в видеопамяти с доступом CPU: окно BAR 256 МБ или Resizable BAR, если он включён. Если такой памяти нет или она закончилась, VMA откатывается на обычную host-visible память. Эта память write-combined: Prepare только пишет в неё и собирает каждую структуру на стеке, копируя целиком.

### 1.0 Сглаживание (MSAA)

`EngineConfig::msaa` (по умолчанию 4) или `Amper.SetAntialiasing(n)` во время игры: 1 — выкл, 2, 4, 8. Значение урезается вниз до поддерживаемого: учитываются лимиты устройства и оба формата целей (бывают пропуски, например только 1× и 4×). Смена применяется в начале следующего `Render`: ожидание GPU, пересоздание целей и пайплайнов.

При MSAA основной проход рисует в мультисэмпловый цвет (transient) и мультисэмпловую глубину; resolve делает dynamic rendering (`VK_RESOLVE_MODE_AVERAGE_BIT`) прямо в изображение swapchain. Карты теней рисуются без MSAA. Фрагментный шейдер выполняется один раз на пиксель (без sample shading), поэтому сглаживаются края геометрии; блики и края RT-теней внутри треугольников MSAA не сглаживает.

### 1.1 Отсечение

Для каждого меша при создании вычисляется ограничивающая сфера (центр AABB, радиус до самой дальней вершины). В мире: центр × матрица модели, радиус × максимальный модуль масштаба.

| Проход | Тест |
|---|---|
| камера | сфера против 5 плоскостей фрустума (ближняя 0,05 м и 4 боковых; дальней нет — reverse-Z до бесконечности) |
| каскад k | в пространстве света сфера пересекает квадрат каскада по X/Y (с запасом 4 текселя на normal offset и PCF) и не лежит целиком дальше его дальней границы |

Ближнюю границу каскада не проверяем: тенеотбрасыватели ближе неё сохраняются «пэнкейкингом». Поэтому объект вне экрана, тень которого падает в кадр, попадает в проход каскада.

Вершинные шейдеры берут инстанс через индекс: `instances[drawIndices[gl_InstanceIndex]]` (binding 5). Буфер инстансов и TLAS содержат все видимые сущности: лучам нужны и объекты вне экрана.

## 2. Модель освещения

### 2.1 Материал

Поля — в [API.md](API.md#material-и-vertex). Параметры и индексы текстур хранятся в инстансе (`GpuInstance`, 144 байта): матрица, цвет/roughness, свечение/metallic, 4 индекса текстур, `normalScale`, `alphaCutoff`, сила и индекс occlusion, `uvScale`.

Текстуры — один bindless-массив `sampler2D textures[]` (set 1, binding 0; descriptor indexing из Vulkan 1.2, update-after-bind, partially bound). Индекс `0xFFFFFFFF` — текстуры нет. Сэмплер общий: линейный, мип-мапы, repeat, анизотропия ×8, если GPU умеет. baseColor и emissive — `R8G8B8A8_SRGB`, остальные — `UNORM`.

Во фрагментном шейдере:

1. `base = color × baseColorMap`; если `alphaCutoff > 0` и `base.a < alphaCutoff` — `discard`;
2. `roughness × mr.g`, `metallic × mr.b`;
3. карта нормалей: TBN из интерполированных нормали и касательной (с ортогонализацией), `xy × normalScale`;
4. двусторонний материал: для задних граней нормаль переворачивается;
5. occlusion гасит только окружение (ambient и отражение неба), прямой свет — нет;
6. `emissive × emissiveMap`.

Нормальная матрица считается в вершинном шейдере (`transpose(inverse(mat3(model)))`): у частей моделей матрица узла может содержать поворот и неравномерный масштаб.

### 2.2 BRDF

Cook–Torrance:

- нормальное распределение — GGX: `D = a² / (π ((n·h)² (a² − 1) + 1)²)`, `a = roughness²`;
- геометрия — Smith со Schlick-GGX, `k = (roughness + 1)² / 8`;
- Френель — Schlick, `F0 = mix(0.04, albedo, metallic)`;
- диффузная часть — Ламберт, `(1 − F)(1 − metallic) · albedo / π`.

### 2.3 Источники

**Солнце.** Направленный источник: `SetSun(direction, color, intensity)`, `direction` — куда светит.

**Точечные.** `AddPointLight(position, color, intensity, range, castShadows)`. Затухание:

```
f   = d / range
att = clamp(1 − f⁴, 0, 1)² / (d² + 1)
```

Источник не влияет на фрагменты дальше `range`. Максимум — 256 источников. Освещение не кластеризовано: каждый фрагмент перебирает все источники.

**Окружение.** Складывается из:

- полусферического диффузного ambient: `ambient · mix(0.45, 1, n.y · 0.5 + 0.5) · albedo · (1 − metallic)`;
- отражения градиента неба (горизонт → зенит; ниже горизонта — 30 % цвета горизонта) с Френелем `Fr` и множителем `(1 − 0.7 · roughness) · 0.8`. Без этого члена металлические поверхности выглядят чёрными.

### 2.4 Тонмаппинг

Экспозиция умножается на линейный цвет, затем применяется аппроксимация ACES (Narkowicz). Параметры: `SetExposure(float)`, по умолчанию 1.

## 3. Тени

### 3.1 Выбор способа

| Условие | Тени солнца | Тени точечных источников |
|---|---|---|
| RT включён (`RayTracing() == true`) | ray query | ray query, если `castShadows` |
| RT выключен, `Shadows() == true` | каскадные карты | нет |
| RT выключен, `Shadows() == false` | нет | нет |

При включённом RT проход каскадов не выполняется. `SetRayTracing(true)` на GPU без поддержки не включает флаг.

### 3.2 Ray tracing

- BLAS строится по одному на меш при его создании, если устройство поддерживает RT (очередь compute, если она выделена; иначе откат на более общую очередь). Это происходит независимо от текущего значения флага RT, поэтому включение флага на лету не требует пересборки.
- TLAS пересобирается каждый кадр; инстансы с отключённой отбраковкой граней.
- Теневой луч: `rayQueryEXT`, `TerminateOnFirstHit | Opaque`, `tMin = 0.001`. Начало луча смещено вдоль нормали на 0,02 м.
- Для точечных источников `tMax = dist − 0.05`; для солнца 10 000.

### 3.3 Каскадные карты теней

| Параметр | Значение |
|---|---|
| Каскадов | 4 |
| Разрешение | 2048² на каскад, `D32_SFLOAT`, массив из 4 слоёв |
| Дальность | `SetShadowDistance`, по умолчанию 80 м, диапазон 5…1000 |
| Ближняя граница | 0,05 м |

Построение каскадов (`ComputeCascades`):

1. **Разбиение.** «Практическая» схема, `λ = 0.75`:
   `split_i = λ · n · (D / n)^(i/4) + (1 − λ) · (n + (D − n) · i/4)`, где `n = 0.05`, `D` — дальность.
2. **Объём каскада.** Ограничивающая сфера среза фрустума: размер не зависит от поворота камеры. Радиус округляется вверх до 1/16 м.
3. **Привязка к сетке текселей.** Центр сдвигается в пространстве света на целое число текселей, поэтому тени не мерцают при движении камеры.
4. **Ортографическая проекция** вокруг сферы по оси света.

Проход теней:

- cull mode — none; аппаратное смещение глубины: константа 1,0, наклон 1,75;
- «пэнкейкинг»: в вершинном шейдере глубина вершин за ближней плоскостью каскада прижимается к ней (`z = max(z, 0)`), чтобы тенеотбрасыватели вне объёма каскада не пропадали.

Выборка (`SunVisibility` в `mesh_lighting.glsl`):

1. Номер каскада — по глубине фрагмента вдоль взгляда камеры.
2. Normal offset: позиция смещается вдоль нормали на 2 текселя каскада.
3. PCF 3×3 по аппаратному сравнению (`sampler2DArrayShadow`, линейная фильтрация): девять выборок, каждая — 2×2 билинейных сравнений.
4. На последних 10 % дальности тень плавно затухает до 1.

Теневая карта между кадрами находится в `SHADER_READ_ONLY_OPTIMAL`; на время прохода переводится в `DEPTH_ATTACHMENT_OPTIMAL` и обратно. Дескриптор привязан статически.

## 4. Справочник API

### 4.1 `Amper`

| Метод | Описание |
|---|---|
| `bool RayTracingSupported()` | GPU поддерживает ray query и acceleration structures |
| `void SetRayTracing(bool)` | включить RT-тени; при отсутствии поддержки игнорируется |
| `bool RayTracing()` | текущее состояние флага |
| `void SetSun(Vec3 direction, Vec3 color, float intensity)` | солнце; `direction` — куда светит |
| `void SetAmbient(Vec3 color, float intensity)` | ambient |
| `void SetSky(Vec3 zenith, Vec3 horizon)` | цвета градиента неба |
| `void SetExposure(float)` | экспозиция |
| `void SetShadows(bool)` / `bool Shadows()` | каскадные тени (используются при выключенном RT); по умолчанию включены |
| `void SetShadowDistance(float meters)` | дальность каскадных теней |
| `void SetAntialiasing(uint32_t samples)` | MSAA: 1, 2, 4, 8 (§1.0) |
| `uint32_t Antialiasing()` / `MaxAntialiasing()` | текущее / максимальное число сэмплов |
| `bool AntialiasingSupported(uint32_t)` | поддерживает ли GPU это число сэмплов |
| `Light AddPointLight(Vec3 position, Vec3 color, float intensity, float range, bool castShadows = false)` | создать точечный источник |
| `uint32_t LightCount()` | число живых источников |
| `uint32_t DrawCalls()` | draw call'ов в последнем кадре |
| `uint32_t Instances()` | инстансов в основном проходе последнего кадра (после отсечения) |

Начальное значение флага RT — `EngineConfig::rayTracing`.

### 4.2 `Light`

| Метод | Описание |
|---|---|
| `bool Valid()` | источник существует |
| `Light& SetPosition(Vec3)` | позиция |
| `Light& SetColor(Vec3)` | цвет |
| `Light& SetIntensity(float)` | интенсивность |
| `Light& SetRange(float)` | радиус действия |
| `Light& SetCastShadows(bool)` | отбрасывать тени; работает только при включённом RT |
| `void Remove()` | удалить источник |

Дескриптор содержит индекс и поколение; после `Remove` старый дескриптор невалиден. Методы защищены мьютексом и безопасны из задач.

## 5. Меши, модели, текстуры

Описаны в [API.md](API.md#mesh). Вершина — 48 байт: позиция, нормаль, UV, касательная. Меши регистрируются по ключу: повторный вызов `Mesh::Cube()` или `Mesh::Sphere(32)` возвращает тот же меш. Геометрия загружается синхронно через очередь transfer.

Модель glTF (`Model::Load`) раскладывается на части «меш + материал + матрица узла». В Prepare каждая сущность с моделью даёт по инстансу на часть (матрица = матрица сущности × матрица узла); инстансы группируются по «меш + односторонний/двусторонний», один draw на группу. Двусторонние группы рисуются отдельным пайплайном без отсечения задних граней. В TLAS каждая часть — свой инстанс.

### 5.1 Анимации

Сущность с анимированной моделью (скин или анимации узлов) получает в Amper аниматор: текущий и предыдущий клип, время, скорость, переход. Команды `PlayAnimation`/`StopAnimation` доходят до него через счётчик команд в данных сущности (как остальные отложенные команды мира).

Prepare:

1. Аниматоры синхронизируются с сущностями; исчезнувшие сущности отдают ресурсы, освобождаются они через `kFramesInFlight` кадров (кадры в полёте могли их читать).
2. Поза каждого аниматора (параллельно): поза по умолчанию → каналы клипа → при переходе смешивание с позой старого клипа (lerp/slerp, вес растёт линейно за `fadeSeconds`) → глобальные матрицы узлов (родитель раньше детей).
3. Палитры костей всех скинов кадра — в один буфер (`joint = global[кость] × inverseBind`).
4. Части без скина у анимированной модели берут матрицу своего узла из позы, а не запечённую.

Render, до TLAS и отрисовки: `skin.comp` (64 вершины на группу, адреса буферов через `buffer_reference`) пишет скиннутые вершины сущности в её буфер, затем обновляются BLAS скиннутых частей (`ALLOW_UPDATE`, режим UPDATE после первой сборки). Растеризация и карты теней рисуют скиннутую часть со своим вершинным буфером и индексами исходного меша — отдельный draw на часть; сферой отсечения скиннутые части не отсекаются (поза выходит за сферу позы по умолчанию).

## 6. Ограничения

- Нет постобработки (кроме тонмаппинга). Сглаживание — только MSAA (без TAA/FXAA): блики и жёсткие края RT-теней не сглаживаются.
- Прозрачность — только alpha cutoff, без смешивания (BLEND из glTF рисуется как MASK 0,5). Тени (и карты, и RT) не учитывают alpha cutoff: вырезанные пиксели отбрасывают тень.
- Текстуры: только 8 бит на канал, без сжатых форматов (BC/ASTC/KTX2) — в видеопамяти несжатые RGBA8.
- Тени точечных источников — только через RT.
- Отсечение — на CPU, по сферам; по перекрытию (occlusion) не отсекается. GPU-driven вариант (compute + `vkCmdDrawIndexedIndirectCount`) потребует общих буферов вершин и индексов для всех мешей.
- Освещение не кластеризовано.
- Анимации: без морфинга, до 4 костей на вершину, скиннутые части не отсекаются и рисуются по одной (без инстансинга); BLAS только обновляется, при очень сильных деформациях качество BVH падает.
- Без Resizable BAR окно видеопамяти с доступом CPU — 256 МБ на всё приложение; при большом числе инстансов часть буферов уйдёт в host-visible память.
- Compute-очередь не пересекается с графикой внутри кадра: используется только для BLAS.
