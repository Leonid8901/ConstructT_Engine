# Nav — навигация

Navmesh и поиск пути на [Recast/Detour](https://github.com/recastnavigation/recastnavigation) v1.6.0 (на ней же сделана навигация Unreal и Unity). Сетку строит Recast, пути и запросы — Detour; агентов, которые сами идут к цели, ведёт движок. Публичный API — `include/CE/Nav.h`, объект `Nav`.

```cpp
void OnStart() override {
    // ... пол и стены: тела BodyType::Static ...
    Nav.Build();                                          // один раз, когда уровень собран

    Entity monster = World.Spawn().SetMesh(m).SetPosition(p).AddBody(capsuleBody);
    NavAgent agent = Nav.CreateAgent(monster);            // можно сразу в той же задаче, где создали сущность
    UniX.CreateTask.NewTask("Chase", Cost::Low, Priority::Normal, [agent](Task&) mutable {
        agent.MoveTo(Camera.Position());                  // путь строится и ведётся сам
    });
}
```

`MoveTo` можно звать каждый кадр с меняющейся целью: если цель сдвинулась меньше чем на 25 см, путь не перестраивается.

## 1. Откуда берётся сетка

Из статических тел Grave (`BodyType::Static`), не триггеров:

| Тело | В сетку попадает |
|---|---|
| Box | как есть, с учётом поворота |
| Plane | квадрат, накрывающий область сетки (плоскость бесконечна, нужна граница) |
| Sphere, Capsule | габаритный бокс (приближение) |
| Dynamic, Kinematic, триггеры | не попадают |

Область сетки — габариты статических тел плюс запас (не меньше 5 м), по высоте включает и плоскость. Задать вручную: `NavConfig::useBounds`, `boundsMin`, `boundsMax` (обязательно, если в мире одна плоскость и боксов нет). Слои: `layerMask` выбирает, тела каких слоёв Grave считаются геометрией. Так делается «открытая/закрытая дверь»: бокс-дверь на своём слое, и сетка пересобирается с маской, включающей его или нет.

Рамки задаёт `NavConfig`:

| Поле | По умолчанию | Смысл |
|---|---|---|
| `agentRadius` | 0,4 м | сетка отступает от стен на радиус |
| `agentHeight` | 1,8 м | низкие проходы (ниже роста) не считаются проходимыми |
| `maxClimb` | 0,4 м | ступенька, на которую можно подняться и с которой можно сойти |
| `maxSlope` | 45° | круче — не проходимо |
| `cellSize` | 0 → радиус / 2 | точность. Меньше — точнее и дольше |

Если область огромна, клетка увеличивается сама (в лог пишется строка), чтобы сетка не съела память: потолок 4 млн клеток (2000 × 2000 при 0,2 м → карта 400 × 400 м). Для больших уровней ограничивайте область.

Сетка одна, под одного «стандартного» агента. Сильно отличающихся по размеру существ (человек и огромный босс) пока не поддерживает.

`Build` синхронный: тестовая сцена из десятка тел — 7–11 мс (Release). Вызывать из `OnStart` или из фоновой задачи (`Once` + `Extreme`); тела, созданные в той же стадии, ещё не попали в физику, поэтому для уровня, собираемого в задачах, стройте сетку на следующий кадр. Повторный `Build` подменяет сетку без остановки запросов; агенты сами перестраивают пути.

Небольшие изолированные площадки (меньше 8 × 8 клеток, ≈ 2,5 м² при клетке 0,2 м) Recast отбрасывает как шум.

## 2. Запросы

Потокобезопасны, можно звать из `ParallelFor`.

| Метод | Что делает |
|---|---|
| `bool FindPath(from, to, NavPath&)` | путь ломаной по точкам поворотов. `false` — старт или цель дальше ≈ 2 м от сетки либо пути нет. Недостижимая цель: путь ведёт в ближайшую к ней достижимую точку, `partial = true` |
| `bool NearestPoint(p, out, radius = 2)` | ближайшая точка сетки |
| `bool RandomPoint(out)` | любая точка сетки, **в том числе на недостижимых площадках** (крыша, замкнутая комната) |
| `bool RandomPointAround(center, radius, out)` | точка не дальше `radius` от `center` (точки на сетке) и достижимая от него без обходов |
| `bool Raycast(from, to, NavHit&)` | луч по сетке: `true` — упёрся в край (стена, обрыв). Видна ли цель «пешком» |
| `Ready()`, `PolygonCount()`, `Clear()` | |
| `DebugGeometry(vertices, indices, lift)` | треугольники сетки для отладочной отрисовки: `Mesh::Create(v, i)` и сущность с зелёным материалом (см. Sandbox, клавиша H) |

## 3. Агенты

`NavAgent` — сущность, которая идёт по сетке сама. Параметры (`NavAgentParams`): `speed` (3,5 м/с), `acceleration` (20 м/с²: разгон и торможение), `turnSpeed` (10 рад/с: поворот лицом по ходу), `stopDistance` (0,3 м), `footOffset` (от центра сущности до пола; по умолчанию половина `agentHeight`).

Как агент двигает сущность — по её телу:

| Тело | Как |
|---|---|
| `Dynamic` | горизонтальная скорость; вертикаль остаётся гравитации и контактам. Задайте `lockRotation`, иначе физика может завалить сущность |
| `Kinematic` | скорость; высота подтягивается к сетке |
| нет тела / `Static` | прямое перемещение, высота плавно следует сетке |

Агент тормозит перед целью сам (скорость ограничена так, чтобы остановиться за `stopDistance` при заданном `acceleration`). Если его унесло или телепортировало дальше 2 м от пути, либо он целую секунду стоит на месте, путь строится заново от текущего положения. Если цели нет на сетке, `MoveTo` возвращает `false` и агент останавливается.

| `NavAgent` | |
|---|---|
| `bool MoveTo(Vec3)` | `false` — цели нет на сетке или путь не построился. Недостижимая цель: идёт в ближайшую достижимую точку, `Partial()` |
| `Stop()`, `Remove()` | |
| `Moving()`, `Arrived()`, `Partial()`, `Target()`, `RemainingDistance()` | состояние (на начало кадра) |
| `SetSpeed(m/s)` | |
| `Valid()` | `false` после `Remove` или удаления сущности (агент уходит вместе с ней) |

Агенты обновляются в главном потоке после физики (`Nav.Update`), поэтому скорость, которую они записывают, попадает уже в следующий шаг Grave. Столкновений агентов друг с другом (избегания) нет: путь строится по сетке, а толкаются они физикой.

## 4. Что проверено

Тест (Linux, программный Vulkan): стена с дверью на отдельном слое; закрытая дверь — обход, открытая — прямой путь; ступенька 0,3 м проходима, бордюр 0,6 м обходится; цель на крыше блока недостижима и даёт частичный путь; луч упирается в стену и проходит в дверь; 1600 параллельных запросов (4 потока) во время 4 пересборок — без отказов; три агента (динамическое, кинематическое тело и без тела) обходят стену, приходят к цели и останавливаются, сетка пересобирается на ходу; агент на сущности, созданной в задаче; удаление сущности убирает агента. 253 проверки: Debug, Release, ASan + UBSan — чисто; ThreadSanitizer — гонок в коде движка нет (два срабатывания внутри драйвера Mesa llvmpipe).

Не проверено: Windows/MSVC, аппаратные GPU (навигация от GPU не зависит), большие карты (сотни метров), много агентов (десятки).

## 5. Пределы

- Одна сетка под один размер агента; динамических препятствий (двери, двигающиеся стены) нет — пересборка через `Build`.
- Нет off-mesh связей (прыжки, лестницы, телепорты) и областей с разной ценой (вода, грязь).
- Меш-геометрия из моделей glTF в сетку не попадает: только коллайдеры Grave. Сложный интерьер собирайте из боксов.
- Агенты не избегают друг друга.
