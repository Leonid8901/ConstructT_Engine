# Модули

Модуль — своя библиотека поверх движка: «скример», «поиск игрока», «инвентарь», «диалоги». Разработчик замечает, что кусок игровой логики повторяется или хочет связать несколько возможностей движка в одну, пишет её **один раз на API движка** и дальше подключает одной строкой и зовёт её методы. Публичный API — `include/CE/Module.h`, объект `Modules`. Готовые примеры: `modules/Jumpscare.h` и `modules/Chase.h`.

```cpp
#include "Jumpscare.h"
#include "Chase.h"

void OnStart() override {
    auto* scare = Modules.Add<lib::Jumpscare>();    // nullptr — игрок выключил модуль в engine.json
    auto* chase = Modules.Add<lib::Chase>();
    if (chase) {
        chase->OnCatch([scare](Entity) { if (scare) scare->Trigger(); });
        chase->Add(monster);                         // враг патрулирует, видит, гонится сам
    }
}
```

## 1. Как устроен модуль

```cpp
class Jumpscare : public ce::Module {
public:
    const char* Name() const override { return "Jumpscare"; }   // уникальное: по нему ищутся настройки и логи
    void OnLoad() override {
        m_cooldown = Settings().Number("cooldown", 8.0f);          // из engine.json или по умолчанию
        NewTask("Effects", Cost::Low, Priority::Normal, [this](Task&) { Tick(); });
    }
    void OnUnload() override { /* убрать за собой: свет, сущности */ }
    bool Trigger(float intensity = 1.0f);                         // свои методы — как угодно
};
```

- **Подключение:** `Modules.Add<T>(args...)` создаёт модуль (аргументы идут в конструктор) и сразу вызывает `OnLoad` в вызывающем потоке. Повторный `Add` того же типа возвращает уже загруженный (аргументы игнорируются). `Modules.Get<T>()`, `Modules.Find("Имя")`, `Modules.Names()` — найти.
- **Зависимости:** `Require<T>()` внутри `OnLoad` загружает нужный модуль, если его ещё нет, и возвращает ссылку. Зависимость всегда загружена раньше зависимого и выгрузится позже. Циклы (A требует B, B требует A) и зависимость от самого себя — исключение с понятным текстом; модули цикла не остаются.
- **Задачи:** `NewTask(...)` — обычная задача UniX, но привязанная к модулю: при выгрузке она останавливается сама, имя получает префикс `Имя.`. Таймеры и обработчики, которые модуль ставит сам, он отменяет в `OnUnload`.
- **Выгрузка:** `Modules.Remove<T>()` выгружает модуль и всех, кто от него зависит (сначала зависимых). При выходе из игры выгружаются все в порядке, обратном загрузке. `OnUnload` вызывается, пока движок ещё работает.
- **Ошибки:** исключение из `OnLoad` — модуль не загружен и не остаётся в реестре (модули, которые он успел загрузить как зависимости, остаются), исключение летит вызвавшему `Add`. Исключение из `OnUnload` пишется в лог и не мешает выгрузке остальных.

## 2. Настройки: engine.json

Рядом с exe, раздел `"modules"` (при первом запуске движок создаёт файл с пустым разделом):

```json
"modules": {
  "Jumpscare": { "cooldown": 15, "flash": false, "fovKick": false },
  "Chase":     { "sight": 12, "chaseSpeed": 3.5 },
  "Inventory": { "enabled": false }
}
```

- `"enabled": false` — модуль не загружается вообще; `Add` вернёт `nullptr`. Если его требует другой модуль, тот тоже не загрузится (в лог пишется причина, ошибкой это не считается). Так игрок отключает скримеры или мигающие вспышки, не дожидаясь патча.
- Остальные поля читает сам модуль через `Settings().Number/Bool/String/Has(ключ, значение по умолчанию)`. Нет файла, раздела или поля — используется значение по умолчанию. Значение не того типа (например, `"auto"` там, где ждут число) тоже считается отсутствующим.
- Имя раздела — это `Name()` модуля. Названия модулей в игре не должны повторяться.

## 3. Потоки и правила

- `Add`, `Remove`, `Get` потокобезопасны (внутри один рекурсивный замок), но `OnLoad`/`OnUnload` выполняются в вызывающем потоке. Звать `Add` и `Remove` лучше из `OnStart`, `OnShutdown`, таймеров и обработчиков триггеров — то есть из главного потока вне стадий. **`Remove` из обычной задачи UniX опасен**: другие задачи этого кадра могут ещё обращаться к модулю.
- Методы, которые игра зовёт из задач (как `Jumpscare::Trigger`), модуль делает потокобезопасными сам. Так же устроены примеры: `Trigger` только запоминает запрос, а эффекты применяет задача самого модуля.
- Указатель на модуль живёт до `Remove` или конца игры. Не храните его дольше.

## 4. Чего здесь нет (и почему)

Модуль собирается **вместе с игрой**: это обычный C++, чаще один заголовок. Движок не читает и не подставляет код во время работы, а компилятор сам встраивает вызовы модуля в игру, поэтому дополнительных затрат на «переход» в модуль нет. Взамен:

- **Нет динамической загрузки** (`.dll`/`.so`) и горячей перезагрузки: у C++ нет стабильного ABI между компиляторами, а динамические модули заставили бы вводить версионирование интерфейсов. Это можно добавить отдельно, когда понадобится.
- **Нет скриптового языка.** Модуль пишется на C++ и тем же API, что и игра.
- **Нет проверки версий** между модулем и движком: модуль собирается с тем движком, что и игра.
- **Нет «магазина» модулей и менеджера пакетов**: чужой модуль — это папка с заголовками, которую вы кладёте в проект.

## 5. Примеры

### Jumpscare (`modules/Jumpscare.h`)
Резкий звук, вспышка света в позиции камеры, рывок угла обзора (`Camera.SetFov`), перезарядка между скримерами. Поля `engine.json`: `cooldown` (8 с), `volume` (1), `flash` (true), `fovKick` (true). `Trigger(intensity)` вернёт `false` на перезарядке. Звук собирается из сэмплов в коде (без файлов).

### Chase (`modules/Chase.h`)
Патруль → заметил → погоня → потерял → поиск у последнего места → патруль. «Видит» = в пределах `sight`, в конусе `fov` (или ближе `hearing`, тогда и спиной) и между ним и игроком нет стен (`Grave.Raycast`). Передвижение — `Nav`-агент (нужен построенный navmesh). События `OnSpot`, `OnLose`, `OnCatch` приходят в главном потоке в конце кадра (через `Timer.After(0)`), там можно трогать мир. Игрок по умолчанию — камера, `SetTarget(fn)` задаёт свою позицию. Параметры врага: `Add(entity, ChaseParams{...})`; общие значения по умолчанию — из `engine.json` (`sight`, `loseTime`, `chaseSpeed`, `patrolSpeed`, `catchDistance`).

Пределы Chase: один игрок; враги не избегают друг друга (это ограничение Nav); линию видимости могут закрывать любые тела Grave, в том числе летящие шары; патруль по случайным точкам вокруг места, где враг добавлен.

## 6. Порядок в кадре

Модули ничего не добавляют в цикл кадра: их задачи — обычные задачи UniX в своих стадиях, а обработчики и таймеры идут там же, где у остальных.
